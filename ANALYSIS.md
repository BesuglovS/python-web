## 2. Сильные стороны

1. **Полнота контента** — 50 уроков охватывают Python от установки IDE до Git, продуманная траектория обучения.
2. **Интерактивность** — Python-REPL (песочница), редактируемые блоки кода, выполнение прямо в браузере.
3. **Система самопроверки** — 10 вопросов к каждому уроку + итоговый тест на 51 вопрос (всего **551 вопрос**).
4. **Геймификация** — прогресс-бар, бейджи (19 достижений), отслеживание серий (streak).
5. **UX-детали** — тёмная/светлая тема, поиск по темам, мобильное меню-гамбургер, кнопка «наверх», оглавление урока (TOC) с отслеживанием позиции, клавиатурная навигация (← →).
6. **Адаптивная вёрстка** — grid-сетка, медиа-запросы, flexbox.
7. **SEO** — Open Graph, Twitter Cards, JSON-LD (Course), sitemap.xml, robots.txt, canonical.
8. **Производительность** — preconnect к CDN, Service Worker со stale-while-revalidate, CSS-переменные.
9. **Доступность** — aria-label, semantic HTML, alt-тексты.

## 3. Проблемы и возможности для улучшения

### 3.1. Производительность (Performance)

| # | Проблема | Приоритет | Рекомендация |
|---|----------|-----------|--------------|
| P1 | **config.js весит ~780 строк** (все 551 вопрос загружаются на каждой странице) | 🔴 Высокий | Разбить квизы на отдельные JSON-файлы по урокам, загружать асинхронно только нужный. Либо генерировать `config.js` динамически при сборке с code-splitting. |
| P2 | **CSS в index.html** — ~200 строк инлайн-стилей в `<style>` внутри `<head>` | 🟡 Средний | Вынести в `style.css` или отдельный `index.css`. Инлайн-стили блокируют рендеринг и не кешируются отдельно. |
| P3 | **Service Worker кеширует все 55+ HTML** при первой установке — медленная установка | 🟡 Средний | Использовать стратегию кеширования по мере посещения (cache-first с обновлением), а не предзагрузку всех страниц. |
| P4 | **CDN highlight.js загружается синхронно в `<head>`** без `defer`/`async` | 🟡 Средний | Добавить `defer` к скрипту или загружать динамически. |
| P5 | **Отсутствует оптимизация изображений** | 🟢 Низкий | `favicon.png` — единственное изображение. Можно добавить формат WebP. |

### 3.2. Кодовая база (Code Quality)

| # | Проблема | Приоритет | Рекомендация |
|---|----------|-----------|--------------|
| C1 | **Дублирование структуры уроков** — список уроков прописан в трёх местах: `lessons.json`, `sw.js` (массив для кеширования), `script.js` (мобильное меню) | 🔴 Высокий | Использовать `lessons.json` как единственный источник истины. Генерировать массив в SW и меню динамически из JSON. |
| C2 | **Весь JavaScript в глобальной области видимости** — переменные `THEORY_CONTESTS`, `CONTEST_BASE_URL`, `LESSON_QUIZZES`, `BADGES` и пр. в глобальном scope | 🟡 Средний | Обернуть в IIFE или модули. В долгосрочной перспективе — перейти на ES6-модули (`type="module"`). |
| C3 | **Смешение var/let/const** — местами используется `var`, местами `let` | 🟡 Средний | Унифицировать на `const` (преимущественно) + `let`. `var` не использовать. |
| C4 | **Отсутствует сборка/бандлинг** — нет минификации CSS/JS, нет транспиляции | 🟡 Средний | Добавить простой build-шаг (например, через Gulp/Webpack/Vite) для минификации и cache-busting. |
| C5 | **Дублирование escapeHtml()** — функция определена и в `script.js`, и в инлайн-скрипте `repl.html` | 🟢 Низкий | Оставить одну версию в `script.js`. |
| C6 | **Инлайн-стили для REPL** — `repl.html` содержит ~250 строк CSS в `<style>` | 🟢 Низкий | Вынести в `style.css` с компонентным подходом. |
| C7 | **Нет строгого режима** — отсутствует `'use strict'` | 🟢 Низкий | Добавить `'use strict'` в начало `script.js`. |
| C8 | **Смешение табов и пробелов в HTML-файлах** — например, `03-variables.html` использует смешанные отступы | 🟢 Низкий | Настроить `.editorconfig`, применить форматирование. |

## 4. Приоритезированный план улучшений

### 🔴 Критические (архитектурные)

1. **Устранить дублирование списка уроков** — `lessons.json` как единый источник, генерация SW-списка и мобильного меню из него.
2. **Шаблонизация страниц уроков** — переход на генератор статики (рекомендую **Eleventy/11ty** с Nunjucks) для устранения 50+ дублирующихся HTML-файлов.
3. **Code-splitting для config.js** — ленивая загрузка квизов только для просматриваемого урока.

### 🟡 Важные (качество и UX)

4. Вынести инлайн-стили (index.html, repl.html) в `style.css`.
5. Добавить CSP и SRI для CDN-ресурсов.
6. Унифицировать стиль кода: `const`/`let`, `'use strict'`, `.editorconfig`.
7. Добавить минификацию и cache-busting через build-шаг.
8. Оптимизировать Service Worker (кеширование по требованию).
9. Улучшить уникальность мета-заголовков уроков.
10. Добавить индикатор загрузки страницы.

### 🟢 Желательные (полировка)

11. Добавить print-стили.
12. Добавить индикаторы прогресса в мобильное меню.
13. Проверить a11y-контраст в тёмной теме.
14. Добавить skip-to-content.
15. Периодический аудит через Lighthouse.
