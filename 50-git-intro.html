Урок 50 Git

Git — это система контроля версий, которая отслеживает изменения в коде и позволяет работать над проектом команде. Практически все современные проекты на Python используют Git.

📌 Зачем нужен Git?

  • История изменений — можно вернуться к любой предыдущей версии кода.
  • Параллельная работа — несколько человек могут работать над проектом одновременно через ветки.
  • Резервное копирование — код хранится не только локально, но и на сервере (GitHub, GitLab).
  • Код-ревью — через Pull Request можно обсуждать изменения перед их принятием.

🔧 Установка Git

  1. Скачать с git-scm.com
  2. Установить, принимая настройки по умолчанию.
  3. Проверить установку:
git --version
# git version 2.44.0

⚙️ Настройка Git

После установки нужно указать имя и email — они будут подписывать каждый коммит:

git config --global user.name "Твоё Имя"
git config --global user.email "your@email.com"

# Проверить настройки
git config --list

📦 Основные команды

Создание репозитория

# Создать новый репозиторий в текущей папке
git init

# Клонировать существующий репозиторий
git clone https://github.com/user/repo.git

Сохранение изменений (коммит)

# Проверить состояние файлов
git status

# Добавить файлы в индекс (staging area)
git add index.html       # один файл
git add .                # все файлы
git add *.py             # по маске

# Создать коммит
git commit -m "Добавил главную страницу"

# Просмотр истории коммитов
git log
git log --oneline        # краткий формат

Отмена изменений

# Отменить изменения в файле (до git add)
git checkout -- file.py

# Убрать файл из индекса (после git add)
git reset HEAD file.py

# Отменить последний коммит (оставив изменения)
git reset --soft HEAD~1

# Отменить последний коммит (удалив изменения)
git reset --hard HEAD~1
💡 Совет: Всегда проверяй git status перед коммитом, чтобы убедиться, что добавляешь нужные файлы.

🌿 Ветки (branches)

Ветки позволяют разрабатывать новые функции изолированно, не затрагивая основной код.

# Просмотр веток
git branch                # локальные
git branch -a             # все (включая удалённые)

# Создать новую ветку
git branch feature-login

# Переключиться на ветку
git checkout feature-login
# или (новая команда)
git switch feature-login

# Создать и сразу переключиться
git checkout -b feature-signup

# Слить ветку в текущую
git merge feature-login

# Удалить ветку
git branch -d feature-login
💡 Популярный workflow (Git Flow):
main — стабильная версия
develop — ветка разработки
feature/xxx — новые фичи
bugfix/xxx — исправления

🌐 GitHub и удалённые репозитории

GitHub — это облачный сервис для хранения Git-репозиториев. Позволяет делиться кодом и работать в команде.

Связывание с удалённым репозиторием

# Добавить удалённый репозиторий
git remote add origin https://github.com/user/repo.git

# Просмотр удалённых репозиториев
git remote -v

Отправка и получение изменений

# Отправить коммиты на сервер
git push origin main

# Получить изменения с сервера
git pull origin main

# Получить список веток с сервера
git fetch

Pull Request (PR)

  1. Создаёшь ветку, делаешь изменения, коммитишь.
  2. Пушишь ветку на GitHub: git push origin my-feature
  3. На сайте GitHub создаёшь Pull Request.
  4. Коллеги просматривают код, оставляют комментарии.
  5. После одобрения PR сливается (merge) в основную ветку.

🚫 .gitignore

Файл .gitignore указывает, какие файлы и папки Git должен игнорировать.

# Пример .gitignore для Python проекта
__pycache__/
*.pyc
*.pyo
.env
venv/
.vscode/
*.log
.DS_Store
node_modules/

Правила синтаксиса:

  • *.pyc — все файлы с расширением .pyc
  • venv/ — папка venv и всё её содержимое
  • !important.txt — исключение (не игнорировать)
  • # — комментарий

✍️ Практическое задание

  1. Установи Git (если ещё не установлен).
  2. Настрой user.name и user.email.
  3. Создай папку my-python-project и инициализируй в ней репозиторий (git init).
  4. Создай файл main.py с кодом print("Hello, Git!").
  5. Сделай коммит.
  6. Создай ветку feature-greeting.
  7. В этой ветке измени main.py, добавив функцию greet(name).
  8. Сделай коммит и слей ветку обратно в main (или master).
  9. Создай файл .gitignore и добавь в него *.log.
